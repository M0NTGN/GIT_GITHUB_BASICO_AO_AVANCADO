# Seção 09: Markdown

> Seção revisada rapidamente por já possuir domínio de Markdown.

Markdown é usado no GitHub principalmente para **documentação e comunicação**.

```text
README.md
      ↓
Issues
      ↓
Pull Requests
      ↓
Wiki
      ↓
GitHub Pages
```

## Onde utilizo

* `README.md` → apresentação e documentação do projeto
* `Issues` → descrição de tarefas, bugs e requisitos
* `Pull Requests` → contexto e revisão das alterações
* `Wiki` → documentação extensa
* `GitHub Pages` → páginas e documentação publicadas

## Regra profissional

Markdown não serve apenas para "formatar texto".

Use-o para tornar a informação **rápida de entender**.

### Estrutura ideal

```markdown
# O que é?

## Por que existe?

## Como usar?

## Exemplo

## Observações
```

### Boa documentação

```text
Objetivo
   ↓
Contexto
   ↓
Como fazer
   ↓
Exemplo
   ↓
Resultado esperado
```

## Meu padrão

Neste repositório, priorizar:

* títulos curtos;
* listas quando facilitarem leitura;
* blocos de código para comandos;
* tabelas apenas quando comparações ajudarem;
* poucas palavras e muita informação útil.

> **Markdown → transformar conhecimento técnico em informação fácil de consultar.**
